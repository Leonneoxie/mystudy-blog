CUDA 与算子

第一个自定义 CUDA 算子应该验证什么

以向量加法为最小例子，建立从 grid-stride loop、PyTorch 扩展到正确性和性能验收的算子学习闭环。

2026-07-31约 2 分钟入门到进阶
CUDAPyTorch ExtensionKernel Validation

问题背景

第一个 CUDA kernel 很容易停在“能编译、能输出”。但自定义算子的目标不是换一种语法实现加法，而是建立接口、并行映射、正确性和性能证据的完整链路。

一句话结论

一个合格的最小算子至少要回答：线程负责哪些元素、任意 shape 是否正确、dtype/device/contiguous 如何约束、错误如何暴露，以及它在什么规模下比框架基线有意义。

最小 kernel

__global__ void add_kernel(
    const float* x, const float* y, float* out, int64_t n) {
  for (int64_t i = blockIdx.x * blockDim.x + threadIdx.x;
       i < n;
       i += blockDim.x * gridDim.x) {
    out[i] = x[i] + y[i];
  }
}

Grid-stride loop 让同一个 kernel 覆盖任意长度，并允许网格大小与数据长度解耦。包装层还需检查张量位于 CUDA、dtype 一致、元素数量一致，并使用当前 CUDA stream，而不是偷偷同步默认流。

正确性不是只测一个 shape

推荐测试集合：

  • n=0、1、31、32、33 等边界；
  • 非 block size 整数倍；
  • 大张量；
  • 不同 dtype（如果声明支持）；
  • 非连续张量：明确拒绝或正确处理；
  • 多 stream 场景；
  • 与 torch.add 的容差对拍。

性能验证

向量加法通常受显存带宽限制。计时必须预热、使用 CUDA event、同步正确边界，并报告数据规模。小张量可能被 Python 和 launch overhead 主导，自定义 kernel 比 PyTorch 慢并不意外。

start.record()
for _ in range(iters):
    out = custom_add(x, y)
end.record()
torch.cuda.synchronize()
ms = start.elapsed_time(end) / iters

还应对比有效带宽，而不只是毫秒：每个元素读取 x/y 并写出 out，FP32 理论数据量约为 12 * n 字节。该估算忽略缓存和其他开销，但能帮助识别数量级错误。

本机环境边界

MyStudy 当前 PyTorch CUDA runtime 能运行 GPU 张量和 FlashInfer，但自定义 CUDA 扩展还依赖本机 CUDA Toolkit、编译器与 PyTorch ABI 匹配。缺少 nvcc 时可以学习源码、接口和模拟验证，不能把它描述为本机 kernel 实测。
