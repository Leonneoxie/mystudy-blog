先给结论

Kimi K3 的重点不是单独某个新模块，而是四条路线同时推进：用 KDA/Gated MLA 面向百万上下文，用高稀疏 MoE 扩容量，用 Attention Residuals 改善深层信号传播，用原生视觉和长时 agentic 训练扩大任务边界。

以下参数均来自 MoonshotAI 官方仓库；性能榜单属于官方报告结果，仍需结合 harness、工具和 reasoning budget 解读。

1. 官方架构快照

项目Kimi K3 官方规格工程含义

激活参数104B/token单 token 计算远小于总参数但仍不小

2. KDA 解决什么问题

标准 softmax attention 的 KV 状态和计算随序列增长。Kimi Delta Attention 属于线性注意力路线，用可递推状态更新表达历史信息，使长上下文不必始终读取完整 K/V 序列。K3 没有把所有层都换成 KDA，而是保留 24 层 Gated MLA，说明工程目标是在线性效率与内容寻址能力之间组合，而不是宣称一种机制在所有层都更优。

阅读 KDA 时应追踪四个对象：状态如何更新、遗忘/门控如何控制旧信息、并行训练如何实现、推理 kernel 是否真正避免线性增长的 KV 读取。

3. Attention Residuals 为什么值得关注

传统 residual 主要把相邻层连接起来。Attention Residuals 让模型能够对多层历史表示进行注意力式聚合，目标是为超深网络提供更灵活的信息通路。它解决的是层间通信，不是 token 间 self-attention 的替代品。

验收不能只看最终 benchmark，还应比较深层激活尺度、梯度稳定性、额外状态/通信量，以及推理阶段是否引入新的内存访问。

4. 896 专家的意义

K3 每 token 选择 16/896 专家，另有两个 shared expert。官方称 Stable LatentMoE 相比 K2 提升整体 scaling efficiency。对 Serving 而言，896 不是一个营销数字，而是 placement、路由偏斜、All-to-All 和专家小 GEMM 的共同压力。

必测项原因
每层专家负载直方图找热点和长尾专家
dispatch/combine 时间判断通信是否吃掉稀疏收益
每专家 token 数判断小 GEMM 利用率
shared expert 占比计算路径并非完全稀疏

5. 原生多模态不是外挂 OCR

K3 的官方定位是原生文本、图像与视频能力，配置包含 MoonViT-V2。分析时要分开视觉编码、token 压缩/对齐、语言模型融合和 agent 工具链。仅报告图片问答分数，无法证明长视频、文档视觉和工具调用的系统能力。

6. MXFP4/MXFP8 QAT 的部署含义

K3 从 SFT 阶段开始用 MXFP4 权重、MXFP8 激活做 QAT。这里的创新不只是 checkpoint 更小，而是训练数值语义、导出 scale/格式和 runtime kernel 被提前统一。

本课程可做的缩小实践是：在 Qwen3 小模型上模拟 block scale、FP4 权重 fake quant 与 FP8 激活，比较 PTQ 和 QAT，再验证导出格式是否被真实低精度 kernel 消费。不能因为 PyTorch 能加载量化参数，就宣称复现了 K3 的训练或硬件收益。

7. 百万上下文如何正确评测

需要同时报告准确性和成本：needle/retrieval 只是第一层，还应测试多跳关联、跨模态长文档、上下文干扰、prefill 时间、首 token 延迟、状态/KV 字节和长任务中的上下文压缩策略。

官方说明某些 agent benchmark 使用工具或上下文压缩，因此比较模型时必须对齐 harness、工具权限、temperature、top-p 和 reasoning effort。

8. 课程实践路线

  1. 在小张量实现 Delta-rule 状态更新并与序列 oracle 对拍；
  2. 比较 softmax、线性状态与混合层的内存增长；
  3. 用 CPU router 模拟 896/16 路由偏斜；
  4. 对 MXFP4/MXFP8 做数值仿真和导出契约；
  5. 把视觉 token 加入长上下文 workload；
  6. 明确哪些是原理复现、哪些需要大规模训练/集群才能验证。
