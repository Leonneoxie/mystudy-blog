先建立一条主线

Transformer 的核心不是背诵 Q、K、V，而是理解：每个 token 如何读取上下文、如何通过残差通路逐层更新，以及训练时一次处理整段序列、推理时逐 token 生成为何形成完全不同的系统瓶颈。

1. 输入张量和三个投影

设隐藏状态 X 的 shape 为 [B,S,D]：batch、序列长度、隐藏维。线性投影得到：

$$Q=XW_Q,\quad K=XW_K,\quad V=XW_V$$

多头拆分后常见 shape 是 [B,H,S,D_h]，满足 H×D_h=D。Q 表示当前位置要寻找什么，K 表示每个位置提供什么匹配线索，V 是被聚合的信息。

2. Self-Attention 究竟算什么

$$Attention(Q,K,V)=softmax(\frac{QK^T}{\sqrt{D_h}}+M)V$$

QKᵀ 产生 [B,H,S,S] 的相关性。除以 sqrt(D_h) 防止维度增大时点积方差过大，M 用来表达 causal 或 padding mask。

Decoder-only 模型不能看未来 token。mask 必须在 softmax 前应用；若先 softmax 再把概率清零，剩余概率不再归一化。

3. 为什么还需要残差、Norm 和 MLP

Attention 负责 token 间通信，MLP 负责每个 token 内部的非线性变换。残差连接保留稳定的信息与梯度通路，RMSNorm/LayerNorm 控制尺度。

h = x + attention(norm1(x))
y = h + mlp(norm2(h))

现代 LLM 常用 pre-norm。GLU 类 MLP 通常写成 down(act(gate(x)) * up(x))，其参数量和计算量经常高于 Attention 投影。

4. 训练和推理为何不同

阶段输入并行性主要中间状态常见瓶颈
训练完整序列所有 token 并行激活、梯度、优化器计算与显存
Prefill完整 promptprompt token 并行新生成 KVGEMM、Attention
Decode每步一个新 token跨请求组成 batch历史 KV Cache权重/KV 带宽、launch

推理时若每生成一个 token 都重新计算历史 K/V，成本会重复增长。KV Cache 保存各层历史 K/V，新 token 只计算自己的 Q/K/V，再让 Q 读取缓存。

5. KV Cache 为什么成为系统核心

标准 MHA 每个 token、每层需要保存 K 和 V，缓存量近似：

$$2\times L\times S\times H_{kv}\times D_h\times bytes$$

长上下文、高并发时，它可能比权重更快吃满显存。MQA/GQA 减少 KV head 数，Paged KV Cache 减少连续预留造成的碎片，但不会改变“历史状态必须正确寻址”的契约。

6. 手写最小 Attention 做什么测试

scores = q @ k.transpose(-2, -1) / math.sqrt(q.size(-1))
scores = scores.masked_fill(causal_mask, float("-inf"))
probs = torch.softmax(scores.float(), dim=-1).to(q.dtype)
out = probs @ v

测试至少覆盖 S=1、非整齐长度、causal/padding、FP32/FP16、极大输入、全遮蔽行，并与 PyTorch SDPA 对拍。还要比较完整 forward 与“prefill + 多步 decode cache”的逐 token logits。

7. 从基础到工程的学习顺序

  1. 用小张量手算单头 attention；
  2. 实现多头拆分、mask、残差和 MLP；
  3. 加入 RoPE、GQA 和 KV Cache；
  4. 对拍 Hugging Face 小模型 block；
  5. 分别测 prefill/decode；
  6. 再进入 FlashAttention、PagedAttention、MoE 与量化。

如果跳过 shape 和逐层 oracle，直接阅读大型模型源码，很容易只记住类名而不能定位错误。

8. 常见误区

误区为什么不对
Attention 就是模型全部MLP、残差、Norm 和训练目标同样关键
KV Cache 会减少模型计算量它主要避免重复计算历史 K/V，并带来显存代价
上下文长度越长越好还受质量、KV 容量、Attention 算法和调度限制
FlashAttention 改变模型语义核心目标是 IO-aware 的数学等价实现
