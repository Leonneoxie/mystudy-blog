先给结论

DeepSeek V4 的主线是“百万上下文下仍然可计算、可缓存、可训练”：CSA+HCA 混合注意力压缩长上下文成本，mHC 改造层间残差通路，Muon 改善大规模训练收敛，再用领域专家培养与 on-policy distillation 合并能力。

DeepSeek 同时发布 Flash 与 Pro，是两种容量/成本点，而不是简单的“快版”和“高分版”。

1. Flash 与 Pro 的官方规格

模型总参数激活参数上下文发布精度适合讨论的目标
V4-Flash284B13B1MFP4 expert + FP8 其他参数成本、吞吐、较易部署
V4-Pro1.6T49B1MFP4 expert + FP8 其他参数容量、复杂推理、agentic 能力

两者都有 Base 的 FP8 Mixed 版本和后训练版本。模型卡将当前发布称为 preview，结论必须带版本日期。

2. CSA + HCA 混合注意力

V4 将 Compressed Sparse Attention 与 Heavily Compressed Attention 组合。核心不是“稀疏”三个字，而是回答两类问题：哪些历史位置值得精确读取，以及其余历史如何以高度压缩状态保留。

官方报告称，在 1M context 下，V4-Pro 的单 token 推理 FLOPs 为 V3.2 的 27%，KV Cache 为 10%。这是相对于指定 baseline 和场景的官方结果，不应外推成所有长度、硬件和 batch 下都等比例加速。

实践时应检查：稀疏索引如何生成、压缩状态是否可增量更新、边界位置与 causal mask 是否正确、runtime 是否有对应 sparse/compact kernel，以及短上下文下额外开销是否反而占主导。

3. mHC 改变的是层间信息高速路

Manifold-Constrained Hyper-Connections 扩展传统 residual connection，同时用约束保持信号传播稳定。它与 Kimi K3 的 Attention Residuals 都说明前沿模型开始重新设计“层与层怎样通信”，但两者不能因为目标相似就视为同一算法。

一个合格实验要比较：相同参数预算下的训练 loss、梯度/激活尺度、深层稳定性、额外计算和推理内存，而不是只实现公式形状。

4. Muon 优化器为何进入模型创新清单

Muon 对矩阵参数更新进行结构化处理，目标是提高收敛效率与稳定性。V4 官方将其列为核心升级，说明优化器已经成为规模化训练系统的一部分。

课程中可在小 Transformer 上对比 AdamW 与 Muon：固定 token budget、数据、初始化和学习率搜索预算，报告 train loss、validation loss、吞吐、优化器状态显存和数值异常。若只用一套 AdamW 学习率直接套 Muon，比较并不公平。

5. 两阶段后训练

官方描述的流程是：先通过 SFT 与 GRPO 独立培养领域专家，再用 on-policy distillation 把不同能力整合进统一模型。这不同于推理时 MoE router 选择专家；这里的“domain-specific experts”还包含训练组织与能力来源的含义。

验证后训练收益需要拆开 base、SFT/RL 专家、统一蒸馏模型，并固定评测 harness。Max reasoning mode 使用更大思考预算，比较时必须同时报告 token 消耗和时延。

6. FP4 Expert + FP8 其他参数

V4 后训练权重采用混合格式：MoE expert 参数 FP4，多数其他参数 FP8。它反映敏感度与容量分布：专家权重占比巨大，FP4 可显著减小存储和带宽；Attention、router、Norm 等路径可能需要更高精度。

部署验收至少检查 checkpoint metadata、block scale、packing、expert kernel、通信 buffer 精度和是否静默反量化。Flash 模型激活参数少，并不意味着单卡可轻松装下全部 284B 权重。

8. Flash 还是 Pro

选型不能只看榜单。Flash 更适合预算敏感、吞吐优先和验证 V4 runtime 支持；Pro 面向更高知识容量和复杂 agentic 任务，但权重、通信和集群要求显著更高。应先在 API 或官方部署上验证任务收益，再决定是否承担私有化部署成本。

9. 可落地的课程实验

  1. 实现 causal block-sparse attention，与 dense oracle 对拍；
  2. 记录不同稀疏率/长度下 FLOPs、状态字节和误差；
  3. 在小模型对比普通 residual 与受约束 hyper-connection；
  4. 对 AdamW/Muon 做等 token budget 实验；
  5. 构造 MoE FP4、非专家 FP8 的混合量化 IR；
  6. 用 V4-Flash 配置做静态显存与通信预算，不在 6GB GPU 上声称完成模型实跑。

证据边界

本文的规格和架构来自 DeepSeek 官方 Hugging Face 模型卡与技术报告。官方 benchmark 仍是发布方结果；MyStudy 当前设备不具备本地加载 284B/1.6T 权重的条件，因此课程实践聚焦缩小复现、格式检查和系统预算，不伪装成 V4 全模型实测。
